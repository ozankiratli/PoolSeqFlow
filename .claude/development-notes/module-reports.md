# Module reports: what the PDF was, and what it became

Written 2026-10-08 (UTC; the evening of 2026-10-07 in Z's time), against `dev` at `d8b7cee` plus the uncommitted work of that day. Not updated to follow the code.

## The ask

Z, after the first `Project/` run with `keepLowDepthAsZero`: *"Basic stats report should display the results under as tables but better organized. Also basic stats pdf has one table and it doesn't render right. the end of the first column renders on top of the beginning of second at times. Report should not be a list of what table is what. It should show the results and plots etc."*

## What the report had been, since v3.0.0

The report and its wiring arrived together in `381541e` (2026-09-04, "F1 basicstats, and the PDF report every analysis carries") and shipped in every release from v3.0.0 to v3.2.0. Every `report.pdf` any of them published held a header and a table naming the declared files, and nothing else. Three causes, one of them the bug and two of them why nobody saw it.

1. **The folder never reached the template.** `InstallResults` hands `reportShell` the destination as the shell text `$STAGE`. `reportSpec` put it into the JSON spec, and the spec was written with `printf '%s' '<spec>'`, single-quoted, so the template read the literal string `$STAGE` as its folder. Every `Sys.glob` matched nothing, and every section was skipped by the branch meant for "an optional output this run did not produce". Rendering the same template against a real folder by hand gave 10 sections where the published one had 0.
2. **The case asserted what the broken report printed anyway.** `test_a_published_folder_carries_one_pdf_of_everything_in_it` looked for `result.tsv` in the PDF text, and the contents table at the top printed every declared file name whatever happened below it. It passed on a report holding nothing. This is the gates-that-stop-checking pattern again: the assertion was aimed at the right word in the wrong place.
3. **A report that failed to build failed in silence.** The reason was printed to stderr, and Nextflow never shows a successful task's stderr; `InstallResults` succeeds by design when the report fails. Found while debugging this work: a typst syntax error in a header-only table left no trace on the console.

The intended layout would not have satisfied the ask either. Rendered by hand with the folder fixed, it gave every heading a page of its own with the table pushed onto the next (a typst `#pagebreak()` before each section), ran long tables off the page with their last rows overprinted (pandoc wraps a pipe table in a `figure`, and a typst figure does not break across pages), overlapped columns, and printed 15-digit doubles.

**The column overlap Z saw** is pandoc's: when a pipe table has a line longer than `--columns`, pandoc gives each column a fixed fraction of the width from the separator's dash counts, and typst cannot break `diversity.tsv` set in monospace, so it overflows into the next column.

## The release read as "unknown"

A module runs as its own Nextflow pipeline (`nextflow run <store>/<module>/main.nf`), and Nextflow reads `nextflow.config` only beside the entry script, so `workflow.manifest.version` is null there. The README said "Produced by PoolSeqFlow unknown", the report said the same, and `CITATIONS.md` named PoolSeqFlow without a version (the `.bib` had no "Version X used" note for it). `releaseVersion()` in `paths.nf` now reads `version = 'X.Y.Z'` out of `${installDir()}/nextflow.config`, with the same regex `bump-version.sh` writes it with, and refuses when it finds none. `checkModuleCompatible()` still skips its environment check in a module's own run; `analysis.nf` makes that check first, so it was left alone.

## What was decided

**A module may lay out its own report.** The organization Z asked for is specific to what a module computes: basicstats' per-pool table combines `design.tsv`, `diversity.tsv` and `neff.tsv`, and its by-sequence tables pivot `depth.tsv`. A generic renderer cannot know that. So the manifest gains `report`, the name of an `.Rmd` in the module's directory, and the frame knits it as a child under the frame's own header. A module without one gets the generic layout: each declared table and figure under its file name, with no list of files (Z: *"Report should not be a list of what table is what"*). `readManifest()` refuses a `report` that is not a plain `.Rmd` name or is not there, the way it refuses a missing `main.nf`.

**The frame keeps the header and the drawing functions.** `analysis/lib/rmd/report.R` holds `report_read`, `report_files`, `report_number`, `report_table`, `report_image`, `report_plot`, `report_palette` and the generic `report_declared`. A child calls them and reads only the published folder (`POOLSEQFLOW_REPORT_FOLDER`). The header does not come from the folder: the release, the frame, the design notes and the child's path are in the spec `reportShell` writes into the task directory, which is not published. Nothing rebuilds a report from a published folder.

**Figures a report draws exist only in the PDF.** They are views of published tables. Publishing them would have made them declared outputs with manual anchors, and Z asked for the report to show them, not for more files.

**basicstats' `frame` floor was not raised.** An older frame's `readManifest()` returns a fixed map and ignores keys it does not know, so `report` is invisible to it and the module still installs and runs. Z may want the floor raised so that a 3.2.0 installation never shows the old report; that is a choice, recorded here as not made.

**Tables are typst code, not pandoc tables.** `report_table` emits a raw typst block: a `table` with `table.header` (repeated on every page), right-aligned numbers, light striping, cells as typst *string literals* so nothing a sample or sequence is called is read as markup, and a figure made breakable by a show rule.

## What was measured

All on the analysis environment's pandoc 3.12 and typst 0.15.1, with `pdftotext` to read pages back.

- **pandoc's typst template** sets US letter, 1.25in margins (a 6in text block) and justified paragraphs. The frame's template sets 1in margins through YAML front matter (6.5in) and turns justification off; a justified line holding a long path spread its words across the page.
- **A table inside `#layout` still breaks across pages**: a 120-row table measured inside one ran over three pages. So typst itself chooses the size. My first attempt estimated widths in R from glyph widths; measured Libertinus Serif at 10pt is about 0.465em a digit, 0.468em a lowercase letter and 0.624em an uppercase one, bold about 10% wider. The R estimate ran roughly 10% high and turned a 24-pool table onto a landscape page it did not need.
- **Turned pages strand headings.** `page(flipped: true)` forces a page break, and the section heading stayed behind on the page before. Dropped.
- **Measuring a whole table unconstrained never wraps.** `measure()` of a table gives its natural width, so headers that could wrap read as too wide and the table was scaled to unreadable. The second rule tried, and the one the review took apart, was: the natural layout at 10 to 7 points; then the columns of numbers sharing what was left equally (`1fr`), measured with their headers stacked and displayed free to wrap; then that scaled down with `scale()`. Each of the three later steps failed on a shape it had not been tested on (below).
- **The rule that holds, measured cell by cell.** Every cell and every header is measured once at 10 points, and widths scale with the type, so each candidate size costs a sum rather than a layout. A column's least width is its widest cell or the widest part of its header (parts end after an underscore or a dot, or at a space), and its most is its widest cell or its whole header. The natural layout (every column at its most) is tried at 10, 9, 8 and 7 points; then explicit widths at the first size from 10 down to 5 at which the least widths fit, each column given its least and a share of what is left over in proportion to what it lacks of its most, capped at its most; then 4 points. Nothing is scaled, so every layout breaks across pages. Across eleven stress folders (the copy of the `Project/` basicstats folder, synthetic ones from 2 to 100 pools, and four the reviewers built and found failing), every overlapping word went to zero, and the 100-pool folder renders in 4 seconds where the whole-table measuring took 8.
- **Zero-width spaces in cells survive into copied text.** `pdftotext` returned `Y_<U+200B>mapped_<U+200B>Scaffold`. Pasted into `analysis.modules.basicstats.chromosomes`, that name would be refused with a list of names that look identical. Break opportunities are inserted in headers only.
- **A breakable figure orphans its caption.** Sweeping filler length so a table's top caption falls at a page foot: 2 of 9 layouts, and 2 of 13 in a second sweep, left the caption alone on one page and the rows on the next. `#show figure.caption.where(kind: table): it => block(sticky: true, it)` brought both to 0. Breakability is set for table figures only: an image figure that was breakable put its caption on the page after the image.
- **knitr's `knit()` defaults to `error = TRUE`**, which writes an R error into the document and carries on; a top-level `if ... else` split across lines in a chunk published a report reading `## Error`. The template sets `error = FALSE`, so a broken chunk stops the knit and the reason is printed.
- **knitr evaluates chunks in the input file's directory** unless `root.dir` is set, which would have written a report's figures into the installation's `analysis/lib/rmd/`. `reportShell` sets `root.dir` to the task directory.
- **`paste0()` recycles a zero-length argument to `""`**, so a header-only table emitted a stray `,` and typst refused the document. The writer fixture's `result.tsv` is one line, which `read.delim` reads as a header with no rows; that is the case that found it.

## What the review found

A review workflow (four reviewers on the frame, the table functions, basicstats' report and the documentation, each followed by a skeptic told to refute every finding) confirmed 31 findings, several of them the same defect found twice. All were fixed the same day. The ones that changed the design:

- **The generic layout read and formatted every row of a table before showing forty.** Measured by the reviewers: 100,000 rows took 60 seconds in the publish step, a million about 13 to 18 minutes and up to 2 GB, to print 40 rows of `association.tsv`. `report_declared()` now reads `nrows = max_rows` and counts the rest by lines.
- **`report_number()` stopped on `Inf`** (`abs(Inf - round(Inf))` is `NaN`, and the subscripted assignment refused it), which association publishes as `t` for a separated allele, and its whole-number test, `abs(x - round(x)) < 1e-9`, printed every value below 1e-9 as 0, `design_floor` at 13 units included. It now prints `Inf`, `-Inf` and `NaN` as themselves and tests `x == round(x)`.
- **The generic layout reformatted identifiers.** A column whose every value parsed as a number was reprinted, so pool `01` read `1`, a year `2,024`, and a long scaffold number gained commas. Only a column holding decimals and no value with a leading zero is reformatted now.
- **The PDF depended on the task's locale.** Under `LANG` unset or `C`, knitr's capture wrote the report's own escapes as `<U+03C0>`, `<U+2265>` and `<U+200B>` and an accented pool name as bytes; the build succeeded. The template now switches `LC_CTYPE` to the first UTF-8 locale it finds and refuses to build without one.
- **Equal shares for the columns of numbers still overlapped**: a design table with three experimental variables printed "Chromosomes" 3.6pt over "Ploidy", Z's own symptom. **The scaled layout was one unbreakable block**: 60 to 100 long-named pools ran past the page foot and smeared. **And typst's own auto columns squeeze a column below its unbreakable content** when a table is wider than the page, so long pool names ran into the next column. That last one I found myself, after switching to auto columns on a reviewer's suggestion, by running a word-overlap check (`pdftotext -bbox`) over the reviewers' own renders. Together these three are why the rule above measures cells.
- **Sequence order is the tables', not the reference's.** basicstats.R builds `chrom_levels` from the indel table first and the SNP table after, so a sequence with SNPs and no indels lands after the last indel-bearing one. The manual sentence said "the order your reference gives them" and now says "the order the tables give them"; basicstats.R's order was left as it is. The depth plots had been in file-name order (`chr10` before `chr2`) and are now in the tables' order.
- **basicstats.R stopped on a header-only indel table**, which is what a project with no surviving indel publishes, so such a project got no results at all. Pre-existing, outside the report work; one guard in `site_rows`.

Smaller ones: figure 1 drew a merged pool's lower bound as an ordinary point, adjacent panels' tick labels collided (3 of 42 random projects), the grid's first rotated pool name was clipped, the report was quadratic in the number of sequences (2 minutes at 20,000), three figure captions named no file, and the cases had gaps: nothing failed on overlapping columns, on `error = TRUE`, on the design notes, or on the report's own arithmetic. One reviewer left two directories, `long__/` and `short__/`, in the repository root from a render with a relative path; they were removed.

## mds and association, the same day

Written later on 2026-10-08, against the same tree plus everything above. Z, on the basicstats report: *"This looks good. Let's do this for both association and mds too"*. That settles the first open item: both modules now declare `report.Rmd`, at version `20261008.001`, and neither `frame` floor was raised, for the reason given for basicstats.

**What each shows first** follows the order the manual already asks a reader to take. association opens with the phenotype as it was read, because `phenotype.tsv` is where a reversed coding is caught; then what the design can show, both floors among them, so the bold sentence about a floor above 0.05 comes before any site; then the strongest sites per phenotype, `qq.png` and the Manhattan plots. mds opens with the plot and every pool's coordinates; then the eigenvalues as a table and as bars colored by sign; then the corrected distances as a pool-by-pool matrix with a heatmap (diverging at zero, since a negative distance is a result); then what each distance rests on: the shared sites as a matrix, the pairs on fewer than 30 sites, and every pair before and after the correction. A matrix holds at most eight pools as columns, split into tables of even size, and when every pair is on fewer than 30 sites that is one sentence rather than a table of all of them.

**association's site table is read by `data.table::fread`**, for the eleven columns the report shows. Measured on a synthetic `association.tsv` of 1,020,000 rows: the report renders in 3 seconds. data.table is in the analysis baseline, and association's manifest now declares `r-data.table=1.18.6.1` as basicstats' does.

**The allele named at each site.** The table shows, beside each site, the allele with the largest |t| and its slope. A biallelic site's reference row carries the negated slope of the other, so the two |t| are one number up to rounding, and which is larger is noise. In the corpus, pt_wingspan's chr1:700 has |t| 5.346774501780389599 for both A and T read back from the table, and the first rule, a stable order on |t|, named the first row, A at -0.0587; at chr10:1800 the two are 0.802679592830802 and 0.802679592830801, and that rule decided in the fifteenth digit. The rule now compares at six significant digits and, between alleles that tie, names the one whose slope is positive, the same reasoning as mds pinning each axis's sign. At a flagged site *t* is not comparable between implementations, so the steepest slope decides instead. Ties in `perm_p` go to the larger `S`, with every flagged site first in file order, since its `S` is Inf on one implementation and 1e16 on another. No case covers that last rule: the corpus has no two flagged sites at one p.

**One defect found writing the manual section**: "Selected at FDR 0.05" labeled `selected`, which counts `fdr_p` at most 0.05 under whatever `fdr` names, Bonferroni included; the row is now labeled by the column. I also made the bold floor sentence per phenotype, believing a run could mix phenotypes at different floors and print a smaller floor beside "above 0.05". It cannot: `design_floor` is 1/units! for every fit of a run (`association.R`), and ties keep a site above the floor without moving it. The review below found that, and the sentence went back to one for the run.

**The count of sites at the floor** compares `perm_p` with 1.5 times the run's `floor`. A permutation p is a whole number of rearrangements over the count, the observed one always among them, so it is a whole multiple of the floor and the next value above the floor is twice it; the midpoint survives any printing. A relative tolerance (1e-9, then 1e-6) depended on how many digits the two were printed with. association.R prints both to 15 and they agree, but the synthetic three-unit folder printed p to six digits and the report counted 0 of its sites at the floor while every site it showed sat there.

**Renders, all with 0 overlapping words** by `pdf_overlapping_words`: the corpus through each module (mds 4 pages, association 3), the copy of the `Project/` mds folder, 24 pools with long names (mds, 10 pages), three units (association), and the 1,020,000-row table.

**The cases, and that they bite.** `mds`: every row of the distance matrix, read out of `report.md` against `distance.tsv` in `mds.tsv`'s pool order, assembled by awk; the frame case checks the four sections and overlaps. `association`: the design's floor in every column, the count of sites at the floor per phenotype, five site rows built by awk from the two tables (two flagged, the tie at chr1:700, a triallelic site), the level coded 1, and the floor sentence after raising one phenotype's floor to 1/6, a state no run produces, dropped after the review; a depth table of one site checked against the corpus oracle; the frame case checks the four sections, the design's floor and overlaps. `15_analysis_results`: a table cut short says by how much. ## One file per phenotype

Z, on that question: *"Isn't the association data like GWAS, a per site value for a given phenotype? It can be a matrix no? sites as rows, and phenotypes as columns?"* I laid out three shapes: one wide table with a column group per phenotype, the long table with each site's strongest allele and slope added, and one file per phenotype. Z: *"OK. Let's do one file per phenotype. That sounds better. Joining files for comparing sounds good."*

**What association publishes now**: `association_<stem>.tsv` and `alleles_<stem>.tsv` for each phenotype fitted, the stem its name with every character outside `[A-Za-z0-9._-]` made `_`, as the Manhattan plots already name their sequences.
